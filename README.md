# Important Dates Tracker – сервис учёта важных дат

Приложение для учёта важных дат и напоминаний о них на Python с веб-интерфейсом на Django.

## 1. Назначение проекта
Important Dates Tracker – учебное приложение для управления событиями и напоминаниями.
Проект позволяет хранить сведения о событиях, пользователях и напоминаниях, выполнять основные операции
с этими объектами и предоставлять доступ к информации через веб-интерфейс Django.
Проект развивается поэтапно: консольная версия приложения дополняется веб-интерфейсом, переводится на Django-шаблоны и получает слой реляционной базы данных.

## 3. Предметная область
В системе используются четыре основные сущности:
- Напоминание (Reminder) – идентификатор, событие, пользователь, срок напоминания, признаки активности и отправки;
- Событие (Event) – идентификатор, название, дата, категория, пользователь, признак ежегодного события;
- Категория (Category) – идентификатор, название;
- Пользователь (User) – идентификатор, имя, адрес электронной почты.

Для предметной области реализованы собственные Python-классы.
На текущем этапе данные хранятся в JSON-файлах. Django ORM и база данных приложения пока не используются.

## 5. Веб-интерфейс
Веб-часть приложения реализована на Django.
Основные страницы:
- главная страница;
- список напоминаний;
- информация об отдельном напоминании;
- список событий;
- страница стастистики по пользователям.
Для формирования страниц используются Django-шаблоны.
Генерация HTML непосредственно в Python-коде веб-представлений не используется.
Представления подготавливают данные и передают их в шаблоны через контекст.

## 6. Django Template Language
Шаблоны используют возможности Django Template Language.
### Базовый шаблон
Общий шаблон страниц: `templates/base.html`
Он содержит общую HTML-структуру страницы, подключение стилей и JavaScript, навигацию, подвал и блоки для содержимого
отдельных страниц.
Дочерние шаблоны используют наследование:
```text
{% extends "base.html" %}
```
Содержимое отдельных страниц размещается в блоке:
```text
{% block content %}
{% endblock %}
```
Заголовок страницы задаётся через блок:
```text
{% block title %}
{% endblock %}
```
### Включаемые шаблоны
Повторяющиеся фрагменты вынесены в отдельные шаблоны.
Для навигации используется: `templates/includes/navigation.html`
Для карточки напоминания: `reminders/includes/reminder_card.html`
Для отображения статуса напоминания: `reminders/includes/reminder_status.html`
Подключение выполняется с помощью тега:
```text
{% include "reminders/includes/reminder_card.html" %}
```
### Контекст
Представления передают данные в шаблоны через словарь контекста.
Например, для списка напоминаний:
```text
context = {
    "reminders": reminders_data,
}
```
В шаблоне данные доступны по имени переменной:
```text
{% for reminder in reminders %}
```
### Циклы и условия
Для формирования списков используются циклы `{% for %}`. При отсутствии элементов используется `{% empty %}`.
Условия `{% if %}` используются для отображения различного содержимого страницы и состояния напоминания (активно, отменено, просрочено, показано).

## 7. Фильтры шаблонов
В шаблонах используются стандартные фильтры Django Template Language.
Например, количество элементов:
```text
{{ reminders|length }}
```
Для отображения значения по умолчанию:
```text
{{ reminder.event.title|default:"Без названия" }}
```
Фильтры используются для представления данных и не содержат бизнес-логику приложения.

## 8. URL-маршрутизация
Для страниц используются именованные маршруты Django и пространства имён.
Примеры:
```text

{% url 'reminders:list' %}
{% url 'reminders:detail' reminder.id %}
```

Ссылки в шаблонах формируются через `{% url %}`, а не за счёт жёстко заданных адресов.

## 10. Хранение данных
На текущем этапе данные проекта переведены из JSON-файлов в реляционную базу данных SQLite.

### Структура базы данных
Файл базы данных: data/important_dates.sqlite. Схема создаётся скриптом sql/schema.sql.

Таблица `users` (Пользователи):

- `id` INTEGER PRIMARY KEY
- `name` TEXT NOT NULL
- `email` TEXT NOT NULL

Таблица `categories` (Категории):

- `id` INTEGER PRIMARY KEY
- `name` TEXT NOT NULL

Таблица `events` (События):

- `id` INTEGER PRIMARY KEY
- `title` TEXT NOT NULL
- `event_date` TEXT NOT NULL
- `category_id` INTEGER NOT NULL (FOREIGN KEY → categories.id)
- `user_id` INTEGER NOT NULL (FOREIGN KEY → users.id)
- `is_recurring` INTEGER NOT NULL DEFAULT 0

Таблица `reminders` (Напоминания):

- `id` INTEGER PRIMARY KEY
- `event_id` INTEGER NOT NULL (FOREIGN KEY → events.id)
- `user_id` INTEGER NOT NULL (FOREIGN KEY → users.id)
- `remind_before` INTEGER NOT NULL
- `is_sent` INTEGER NOT NULL DEFAULT 0
- `is_active` INTEGER NOT NULL DEFAULT 1

### Перенос данных
Для переноса данных из JSON используется скрипт `db/import_json.py`.
Подключение к базе настраивается в модуле `db/database.py` с включением проверки внешних ключей (`PRAGMA foreign_keys = ON`) и поддержкой доступа к полям по именам (`row_factory = sqlite3.Row`).
Запуск импорта: `python -m db.import_json`.

### SQL-запросы
Все разработанные запросы сохранены в файле `sql/queries.sql`. Они включают:
- выборку списков (`SELECT`);
- фильтрацию (`WHERE`);
- соединение таблиц (`JOIN`);
- агрегатные функции (`COUNT`);
- группировку (`GROUP BY`).

### Использование данных в Django
Django-представления подключаются к SQLite напрямую через модуль `sqlite3`.

- Главная страница: выводит общее количество событий, напоминаний (агрегатные функции) и список пользователей (`SELECT`).
- Напоминания: список с фильтрацией по статусу (активные, просроченные) с использованием `JOIN` и `WHERE`.
- Детали напоминания: получение полной информации по ID через `JOIN` трёх таблиц.
- События: список с поиском по названию (`WHERE`) и вывод событий без напоминаний (`LEFT JOIN`).
- Статистика: выводит количество напоминаний у каждого пользователя (`GROUP BY`).

## 11. Основные модули
- `storage.py` – отвечает за загрузку и сохранение данных из JSON-файлов.

- `models/` – содержит классы предметной области: `Reminder`, `Event`, `Category`, `User`.

- `main.py` – содержит консольный вариант работы с приложением.

- `utils.py` – содержит вспомогательные функции для консольного интерфейса.

- `reminders/views.py` – обрабатывает веб-запросы, связанные с напоминаниями.

- `events/views.py` – обрабатывает веб-запросы, связанные с событиями.

- `homepage/views.py` – содержит представление главной страницы и обработчик ошибки 404.

- `db/` – модули подключения к SQLite и импорта JSON.

- `sql/` – SQL-схема и файл запросов.

## 12. Тестирование
В каталоге `tests/` находятся тесты основных классов предметной области.
Тесты проверяют работу основных операций с напоминаниями, событиями, пользователями и категориями.
Для запуска тестов используется: `pytest -v`

## 13. Проверка качества кода
Для проверки соответствия кода требованиям форматирования и стиля используется `flake8`.
Запуск проверки: `flake8 . --extend-exclude=venv`

## 14. Запуск проекта
Для запуска Django-сервера необходимо перейти в каталог проекта и выполнить:
```text
python manage.py runserver
```
После запуска веб-интерфейс доступен по адресу: `http://127.0.0.1:8000/`
